# Zarqa mascot images

The mascot only works if she looks like the **same character** in every image. Image models drift: they redraw the face, drop the side ornament, add jewelry, make her older or 3D. The fix is a long, fixed prompt plus the character sheet as a reference image, and changing as little as possible between images. Your job is to fill in the few slots that are allowed to change and leave the rest alone.

## Files

- `assets/prompt-template.md`: the full prompt. Everything is locked except the `{{...}}` slots.
- `assets/character-sheet.png`: the canonical character sheet. Always attach it to the image request; the prompt tells the model the sheet is the authority, so a request without it loses most of its consistency. If the file is missing, tell the user and ask them to put it there before generating.

## What can change (the slots)

| Slot | What goes in it |
|---|---|
| `{{POSE_ACTION}}` | What she is doing, in one or two plain sentences. Arm, hand and leg placement follow from it. |
| `{{EXPRESSION}}` | Facial expression, using only her existing features (e.g. "big happy smile, eyes slightly squinted", "worried, eyebrows raised"). |
| `{{GAZE}}` | Where she looks: at the viewer, at the prop, off to the left, etc. |
| `{{PROPS}}` | Only the props the user asked for, described simply. Write "None." if there are none. |
| `{{FRAMING}}` | Full body (default), three-quarter, or head-and-shoulders. |

The sheet already shows her expression range: gentle smile, wink, puzzled (with a "?"), thinking (finger on chin), eyes-closed laugh, and reading a paper. Prefer expressions close to these, and you can point to them in the slot (e.g. "puzzled, as in the sheet's question-mark head").

If the user doesn't specify a slot, pick a sensible default that fits the action (friendly smile, looking at the viewer, full body) rather than asking.

## What is locked

Everything else in the template: her face, eyes, skin, braids, veil, headband, forehead coins, side ornament, earrings, dress, palette, body proportions, cartoon style, and the **transparent PNG background with no scenery**. Don't edit the locked text, don't "improve" it, and don't paste extra description of her appearance into the slots. Adding description is how drift starts: the model treats your words as permission to redraw.

If the user asks for something that touches a locked part (a hat, a different dress colour, a background scene, a 3D version, sunglasses), don't quietly slip it in. Tell them which locked rule it breaks and ask whether this is a one-off exception. If they say yes, make the smallest edit to the template copy for that one image and mention it in your reply.

## Props

Zarqa is a lost-and-found app, so props are usually lost items: AirPods case, keys, wallet, water bottle, laptop, umbrella, student card. Keep props generic and unbranded beyond what's needed to recognise them. Cards (ID, bank, student) must be made-up blank cartoon cards with no real names, numbers or photos. Props shouldn't cover her face, braids, forehead coins or side ornament; if an action would (e.g. "holding a phone to her ear"), choose the side or angle that keeps the ornament visible.

## Steps

Images are generated by the **Codex CLI** (its built-in image generation, signed in with ChatGPT). `scripts/generate.py` does the whole run: fills the template, attaches the character sheet, calls `codex exec`, copies the PNG out, and checks the transparency.

1. Read the user's request and fill the five slots. Fix their typos and phrasing; keep the meaning. Pick a short kebab-case name (e.g. `airpods-handover`).
2. Run from the project root (one run takes about a minute; use a long timeout):
   ```
   python .claude/skills/zarqa-mascot/scripts/generate.py --name <name> --pose "..." --expression "..." --gaze "..." --props "..." --framing "..."
   ```
   It writes to `mascot-output/`: `<name>.png`, `<name>.prompt.md` (the exact prompt, kept for every image), `<name>.preview.jpg` (the image on white) and `<name>.codex-log.txt`. For several images, run them in parallel as separate commands. For an approved exception to a locked rule, edit a copy of the filled prompt and pass it with `--prompt-file`.
3. Look at `<name>.preview.jpg`, not the PNG. Many viewers show the PNG's transparent pixels as a dark glow, which is just hidden colour data, not a real background. Check it against the identity anchors (face, blue eyes, two braids, cream veil, headband, forehead coins, side ornament, palette, proportions, cartoon style). The script prints `TRANSPARENCY: OK`, `SUSPECT` or `NONE`; anything but OK means it isn't a clean cutout, so say so. If an anchor is wrong, regenerate once with the same prompt before changing anything.
4. Show the user the image and briefly say what (if anything) drifted from the sheet.

If Codex fails (not signed in, quota, image generation disabled), read the log, tell the user, and give them the filled prompt in a code block to paste into ChatGPT with the character sheet attached.

## Example

Request: "her holding up an airpods box like she's handing it over"

- POSE_ACTION: Holding up an AirPods box with both hands, arms extended toward the viewer, as if handing it over.
- EXPRESSION: Warm, friendly smile.
- GAZE: Looking at the viewer.
- PROPS: A small white AirPods box, simple cartoon style.
- FRAMING: Full body.
